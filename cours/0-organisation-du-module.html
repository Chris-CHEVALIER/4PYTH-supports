Le module

Organisation du module

Pourquoi Python en cyberdéfense ?

Vous le retrouverez dans vos prochains modules :

  • 4CRYP Cryptologie
  • 4FSIC Forensic
  • 4TECH Audit technique
  • 5REVE Reverse engineering
  • 5XSOC SOC & 5IAAT IA

Des outils de référence écrits en Python :

  • Volatility – analyser la mémoire vive
  • Impacket – dialoguer avec les services Windows
  • sqlmap – tester les injections SQL
  • Scapy – fabriquer des paquets réseau
  • pwntools – écrire des exploits (CTF)
Savoir lire, adapter et écrire un script Python est un réflexe de base de l'analyste, de l'auditeur et du pentesteur.
Motiver les débutants : ce module n'est pas une fin en soi, c'est un outil qui servira dans toute la formation. Inutile de connaître ces outils : ils montrent seulement que Python est partout en cybersécurité. Volatility analyse la mémoire vive (forensic). Impacket parle les protocoles Windows (SMB, Kerberos…) lors d'un audit d'Active Directory. sqlmap automatise la recherche d'injections SQL. Scapy forge des paquets réseau sur mesure. pwntools facilite l'écriture d'exploits dans les CTF. Demander si certains ont déjà utilisé l'un de ces outils.

Objectifs du module

À l'issue du module, vous serez capables de :

  • Écrire un programme Python structuré : types, conditions, boucles, fonctions, gestion des erreurs
  • Modéliser un problème en objets : classes, héritage, composition
  • Lire, écrire et sauvegarder des données : fichiers texte, JSON
  • Utiliser Python comme outil de cybersécurité : contrôle des mots de passe, aléa sécurisé, analyse de journaux, validation des données

Programme

Cours 1 – Fondamentaux

Variables et types, conditions, boucles, listes et dictionnaires, fonctions, exceptions, modules

Cours 2 – Objets

Classes et objets, encapsulation, héritage, polymorphisme, composition

Cours 3 – Données

Fichiers texte, dates, erreurs de fichier, JSON, sauvegarde d'objets

Défis cyber

Exercices courts l'après-midi, à faire sans IA : mots de passe, journaux, comptes… Seuls les défis du 7 octobre sont notés.

Projet fil rouge « Fondation »

3 TP qui s'enchaînent : un programme complet, construit étape par étape, jusqu'à sa sauvegarde

Ce qui change à partir du 9 octobre

  • Projet Fondation : le TP1 démarre le 9 octobre. Vous avancez ensuite à votre rythme, en séance ou chez vous. Le projet complet est à rendre au plus tard le jeudi 5 novembre à 16h30

Annoncer ces ajustements en début de journée, après la correction guidée du défi 1. Rappeler que la soutenance vérifie la compréhension du code : un code produit par l'IA et non compris ne rapporte rien.

Soutenance et examen écrit

Soutenance · 10 min · le 5 novembre

  • 3 min : démonstration de votre programme
  • 7 min : explication d'une partie du code que je choisis, puis une petite modification en direct, sans IA

Examen écrit · 30 min · le 5 novembre

  • 10 questions ouvertes sur l'ensemble des cours
  • Plusieurs questions portent sur des extraits de code à lire ou à corriger
  • Sans documentation ni IA

L'IA générative : autorisée, à une condition

  • ChatGPT, Claude, Copilot… sont autorisés pour le projet
  • Vous devez comprendre votre code de bout en bout. Chaque ligne rendue doit pouvoir être expliquée
  • Déclarez votre usage dans le README : quels outils, pour quoi faire
  • La soutenance vérifie cette compréhension. Une fonctionnalité non expliquée n'est pas comptée
  • Examen et soutenance se font sans IA
  • Le plagiat entre étudiants est sanctionné. L'entraide est encouragée. Expliquer, oui ; donner son code, non
Conseil : utilisez l'IA comme un tuteur (expliquer une erreur, relire votre code), pas comme un auteur.
