Fichiers et données

Ouvrir un fichier


with open("notes.txt", "w", encoding="utf-8") as file:
    file.write("Audit du serveur srv-web\n")

with open("notes.txt", encoding="utf-8") as file:
    content = file.read()
print(content)    # Audit du serveur srv-web
ModeEffet
"r"lecture (par défaut)
"w"écriture, qui écrase le fichier
"a"ajout à la fin

D'autres modes existent, comme "r+" (lecture et écriture). Ils sont décrits dans la documentation de open().

Précisez toujours encoding="utf-8". Sans lui, Windows utilise un autre encodage et les accents deviennent illisibles.
Insister sur "w" : ouvrir un fichier existant en écriture l'efface immédiatement, avant même le premier write().

Écrire et ajouter


from datetime import datetime   # dates et heures

def log_event(message):
    # date et heure actuelles, au format 2026-10-09T10:42:05
    now = datetime.now().isoformat(timespec="seconds")
    with open("actions.log", "a", encoding="utf-8") as file:
        file.write(f"{now} {message}\n")

log_event("Ajout de Jagger Fount")
log_event("Retrait de Hugo Crast")
      

2026-10-09T10:42:05 Ajout de Jagger Fount
2026-10-09T10:42:05 Retrait de Hugo Crast
  • Le module standard datetime gère les dates et les heures
  • Le mode "a" ajoute à la fin du journal
  • write() n'ajoute pas de retour à la ligne. Écrivez le \n vous-même
Un journal horodaté est la première source d'une investigation.

Écrire et lire du JSON


import json

config = {"server": "srv-web", "ports": [22, 443],
          "mfa": True, "owner": "Équipe SOC"}

with open("config.json", "w", encoding="utf-8") as file:
    json.dump(config, file, indent=2, ensure_ascii=False)

with open("config.json", encoding="utf-8") as file:
    loaded = json.load(file)
print(loaded["ports"])            # [22, 443]

text = json.dumps(config)         # dict → str
print(json.loads(text)["mfa"])    # True
  • dump / load : vers ou depuis un fichier
  • dumps / loads : vers ou depuis une chaîne (le « s » de string)
  • indent=2 : un fichier indenté, donc lisible
  • ensure_ascii=False : les accents restent lisibles

Sauvegarder des objets


class User:
    def __init__(self, username, role):
        self.username = username
        self.role = role

    def to_dict(self):
        return {"username": self.username, "role": self.role}


def user_from_dict(data):
    return User(data["username"], data["role"])
        

data = []
for user in users:
    data.append(user.to_dict())
with open("users.json", "w", encoding="utf-8") as file:
    json.dump(data, file, indent=2)
  • JSON ne connaît pas vos classes. json.dumps(users) lève TypeError: Object of type User is not JSON serializable
  • On convertit donc chaque objet en dictionnaire
  • Au chargement, user_from_dict() refait l'objet
  • Chaque classe a son propre to_dict()
Au TP3, une flotte contient des vaisseaux qui contiennent des membres : le to_dict() de Fleet appelle celui de Spaceship, qui appelle celui de chaque membre.

Charger sans planter


def load_users(path):
    try:
        with open(path, encoding="utf-8") as file:
            data = json.load(file)
    except FileNotFoundError:
        return []                # premier lancement
    except json.JSONDecodeError:
        print("Sauvegarde corrompue")
        return []
    users = []
    for item in data:
        users.append(user_from_dict(item))
    return users

print(len(load_users("absent.json")))   # 0
print(len(load_users("users.json")))    # 2
  • Au premier lancement, la sauvegarde n'existe pas encore. Ce n'est pas une erreur
  • Un fichier tronqué ou modifié à la main lève l'erreur json.JSONDecodeError
  • Dans les deux cas, le programme démarre avec des données vides

🛡️ Côté sécurité


ROLES = ["analyste", "auditeur", "admin"]

def user_from_dict(data):
    if data.get("role") not in ROLES:
        raise ValueError(f"rôle inconnu : {data.get('role')}")
    return User(data["username"], data["role"])

user_from_dict({"username": "eve", "role": "root"})
# ValueError: rôle inconnu : root
  • json ne fait que lire des données. Il n'exécute jamais de code
  • Un fichier JSON se modifie pourtant à la main. Les données chargées se valident donc, par liste blanche
Jamais d'eval() (qui exécute une chaîne comme du code Python) sur des données non fiables. Un fichier piégé suffirait à exécuter du code sur votre machine.
Même risque avec le module pickle (sauvegarde binaire d'objets Python) : charger un fichier piégé exécute du code arbitraire. C'est une vraie classe de vulnérabilités (désérialisation non sûre, catégorie de l'OWASP Top 10).
