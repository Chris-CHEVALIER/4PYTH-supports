Le module

Organisation du module

Pourquoi Python en cyberdéfense ?

Vous le retrouverez dans vos prochains modules :

  • 4CRYP Cryptologie
  • 4FSIC Forensic
  • 4TECH Audit technique
  • 5REVE Reverse engineering
  • 5XSOC SOC & 5IAAT IA

Des outils de référence écrits en Python :

  • Volatility – analyse de mémoire
  • Impacket – protocoles Windows
  • sqlmap – injections SQL
  • Scapy – forge de paquets
  • pwntools – exploitation
Savoir lire, adapter et écrire un script Python est un réflexe de base de l'analyste, de l'auditeur et du pentesteur.
Motiver les débutants : ce module n'est pas une fin en soi, c'est un outil qui servira dans toute la formation. Demander si certains ont déjà utilisé l'un de ces outils.

Objectifs du module

À l'issue du module, vous serez capables de :

  • Écrire un programme Python structuré : types, conditions, boucles, fonctions, gestion des erreurs
  • Modéliser un problème en objets : classes, héritage, composition
  • Lire, écrire et sauvegarder des données : fichiers texte et binaires, JSON
  • Utiliser Python comme outil de cybersécurité : octets et encodages, empreintes (hash), aléa sécurisé, analyse de journaux

Programme

Cours 1 – Fondamentaux

Variables et types (dont octets), conditions, boucles, listes et dictionnaires, fonctions, exceptions, modules

Cours 2 – Objets

Classes et objets, encapsulation, héritage, polymorphisme, composition

Cours 3 – Données

Fichiers texte et binaires, JSON, sauvegarde d'objets, analyse de journaux

Défis cyber

Exercices courts en séance, directement liés à chaque cours : mots de passe, empreintes, journaux, cryptographie…

Projet fil rouge « Fondation »

4 TP qui s'enchaînent : un programme complet, construit étape par étape, jusqu'à sa sécurisation

Deux parcours, une même évaluation

Parcours principal

  • Vous découvrez ou reprenez les bases
  • Cours → défis → TP
  • Je vous accompagne en priorité

Parcours confirmé

  • Vous programmez déjà en Python
  • Défis avancés en parallèle : chiffrement, brute force, Man in the Middle
  • Bonus du projet Fondation
Les deux parcours sont évalués selon les mêmes modalités. Le parcours confirmé sert à progresser, pas à gagner des points.
Les « anciens » de 1re année sont orientés vers le parcours confirmé, mais chacun peut changer de parcours à tout moment.

Modalités d'évaluation

ÉpreuveConditionsPoids
Examen écrit ThéorieSur table, sans documentation ni IA50 %
Soutenance individuelle PratiqueDémonstration, explication et modification du code en direct25 %
Projet Fondation PratiqueCode rendu sur GitHub, selon la grille d'évaluation15 %
Défis en séance PratiqueChaque défi : non fait (0), partiel (1) ou réussi (2) ; moyenne des 3 journées10 %
85 % de la note porte sur ce que vous démontrez vous-mêmes, en direct.
Justifier la pondération : à l'heure de l'IA générative, un code rendu ne prouve pas qu'on sait programmer. La note mesure donc surtout ce qui est démontré en personne.

Rendu du projet sur GitHub

  • Un dépôt privé nommé 4pyth-fondation-nom-prenom
  • Invitez Chris-CHEVALIER comme collaborateur au plus tard le vendredi 9 octobre

    • le mode d'emploi du programme ;

    • la déclaration d'usage de l'IA.
Seul le dernier commit poussé avant le jeudi 5 novembre à 16h15 est évalué.

Soutenance et examen écrit

Soutenance · 10 min · le 5 novembre

  • 3 min : démonstration de votre programme
  • 7 min : explication d'une partie du code que je choisis, puis une petite modification en direct, sans IA

Examen écrit · 30 min · le 5 novembre

  • 10 questions ouvertes sur l'ensemble des cours
  • Plusieurs questions portent sur des extraits de code à lire ou à corriger
  • Sans documentation ni IA

L'IA générative : autorisée, à une condition

  • ChatGPT, Claude, Copilot… sont autorisés pour le projet
  • Vous devez comprendre votre code de bout en bout : chaque ligne rendue doit pouvoir être expliquée
  • Déclarez votre usage dans le README : quels outils, pour quoi faire
  • La soutenance vérifie cette compréhension : une fonctionnalité non expliquée n'est pas comptée
  • Examen et soutenance se font sans IA
  • Le plagiat entre étudiants est sanctionné. L'entraide est encouragée : expliquer, oui ; donner son code, non
Conseil : utilisez l'IA comme un tuteur (expliquer une erreur, relire votre code), pas comme un auteur.
