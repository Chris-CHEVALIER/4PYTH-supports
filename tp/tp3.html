1 Des objets aux dictionnaires

≈ 1 hMéthodes · héritage · composition

JSON ne connaît pas vos classes : json.dumps(fleet) provoque une TypeError. Chaque classe doit donc savoir se convertir en dictionnaire, avec une méthode to_dict().

Classeto_dict() renvoie…
Personfirst_name, last_name, gender et age
Operator"type": "operator", les clés de Person, puis role et experience
Mentalist"type": "mentalist", les clés de Person, puis mana
Spaceshipname, ship_type, condition et crew : la liste des to_dict() de chaque membre
Fleetname et spaceships : la liste des to_dict() de chaque vaisseau
Le bon format, vous l'avez déjà Le résultat de fleet.to_dict() a exactement le format de FLEET_DATA du TP2, avec une clé experience en plus pour les opérateurs. Votre build_fleet() saura donc reconstruire la flotte : adaptez-le seulement pour lire l'expérience avec m.get("experience", 0), puisqu'elle est absente de FLEET_DATA. 

      fleet = build_fleet(FLEET_DATA)
      fleet.spaceships[0].crew[0].act()         # Hugo Crast pilote le vaisseau.

      data = fleet.to_dict()
      print(data["spaceships"][0]["crew"][0])
      # {'type': 'operator', 'first_name': 'Hugo', 'last_name': 'Crast', 'gender': 'M',
      #  'age': 37, 'role': 'pilote', 'experience': 1}

      again = build_fleet(data)
      print(again.to_dict() == data)             # True
Indices
  • Revoyez la diapo « Sauvegarder des objets » du cours 3.
  • Dans Operator, ne réécrivez pas les quatre clés de Person : partez de super().to_dict() puis complétez le dictionnaire.
  • Dans Spaceship et Fleet, chaque objet contenu sait déjà se convertir : une boucle qui appelle leur to_dict() suffit. C'est la composition qui travaille pour vous.

2 Sauvegarder et charger

≈ 1 hJSON · fichiers · exceptions

Dans un nouveau fichier storage.py, écrivez :

  1. save_fleet(fleet, path), qui enregistre fleet.to_dict() dans un fichier JSON lisible : indenté, en UTF-8, avec les accents conservés.
  2. load_fleet(path), qui relit le fichier et renvoie un objet Fleet grâce à build_fleet().

load_fleet() ne doit jamais faire planter le programme. Quand le chargement est impossible, elle lève une ValueError avec un message clair, que le menu affichera :

SituationException d'origineMessage conseillé
le fichier n'existe pasFileNotFoundErroraucune sauvegarde « flotte.json »
le JSON est mal forméjson.JSONDecodeErrorla sauvegarde « flotte.json » est corrompue
une clé attendue manqueKeyErrorla sauvegarde « flotte.json » est incomplète
une valeur est interdite (rôle inconnu…)ValueError de vos classesle message de votre classe, tel quel

      save_fleet(fleet, "flotte.json")
      print(load_fleet("flotte.json").to_dict() == fleet.to_dict())   # True

      load_fleet("inexistant.json")
      # ValueError: aucune sauvegarde « inexistant.json »
Indices
  • Revoyez les diapos « Écrire et lire du JSON » et « Charger sans planter » du cours 3.
  • json.dump(data, f, indent=2, ensure_ascii=False) dans un fichier ouvert avec encoding="utf-8".
  • Dans un except, vous pouvez lever une nouvelle exception : raise ValueError("…").

4 Testez comme un attaquant

≈ 30 minValidation des entréesSécurité

Un fichier de sauvegarde se modifie avec n'importe quel éditeur de texte. Mettez-vous à la place d'un utilisateur malveillant : faites une copie de flotte.json, modifiez-la, puis essayez de la charger. Votre programme doit réagir ainsi :

Modification dans la copieComportement attendu
un rôle devient "root"chargement refusé : rôle inconnu : root
un mana devient 9999chargé, mais le mana est ramené à 100 par votre setter
la clé "age" d'un membre est suppriméechargement refusé : sauvegarde incomplète
la dernière accolade } est suppriméechargement refusé : sauvegarde corrompue
Réfléchissez
  • Pour le mana, votre programme corrige la valeur ; pour le rôle, il la refuse. Quelle stratégie est la plus sûre ? Dans quels cas ?
  • Si l'attaquant change un âge de 37 en 38, aucune de vos validations ne le voit : la valeur est plausible. Pour détecter toute modification, il faudra une empreinte de la sauvegarde. Ce sera le TP4.
  • C'est pour éviter ces pièges que l'on utilise JSON et jamais pickle ni eval() sur des données non fiables (cours 3).
