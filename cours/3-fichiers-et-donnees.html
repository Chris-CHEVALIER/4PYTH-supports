Écrire et ajouter


from datetime import datetime

def log_event(message):
    now = datetime.now().isoformat(timespec="seconds")
    with open("actions.log", "a", encoding="utf-8") as f:
        f.write(f"{now} {message}\n")

log_event("Ajout du membre Jagger Fount")
log_event("Retrait du membre Hugo Crast")
      

2026-10-09T10:42:05 Ajout du membre Jagger Fount
2026-10-09T10:42:05 Retrait du membre Hugo Crast
  • Le mode "a" ajoute : relancer le programme allonge le journal
  • write() n'ajoute pas de retour à la ligne : \n est à votre charge
Un journal horodaté est la première source d'une investigation.

Octets et empreintes

Fichiers et données

Texte ou octets ?


text = "Clé"
data = text.encode("utf-8")
print(data)        # b'Cl\xc3\xa9'
print(len(text))   # 3 caractères
print(len(data))   # 4 octets
print(data.decode("utf-8"))   # Clé
  • str : du texte, pour les humains
  • bytes : des octets, pour les machines (fichiers, réseau, cryptographie)
  • encode() : texte → octets ; decode() : octets → texte
  • En UTF-8, é occupe 2 octets
Toute la cryptographie travaille sur des octets : hashlib, chiffrement, sockets. D'où l'importance de cette distinction pour la suite de la formation.

L'hexadécimal


data = "Hi!".encode()
print(data.hex())                 # 486921
print(bytes.fromhex("486921"))    # b'Hi!'

print(int("ff", 16))              # 255
print(hex(443))                   # 0x1bb
  • Un octet s'écrit avec 2 chiffres hexadécimaux : 48 = H
  • C'est la notation des empreintes, des adresses mémoire et des éditeurs hexadécimaux
  • int(texte, 16) convertit depuis la base 16
Vous la retrouverez partout en 4FSIC Forensic et en 5REVE Reverse engineering.

Lire un fichier binaire


SIGNATURES = {
    b"%PDF": "PDF",
    b"\x89PNG": "PNG",
    b"PK": "ZIP (ou docx, xlsx…)",
}

def detect_type(path):
    with open(path, "rb") as f:
        header = f.read(8)
    for magic, kind in SIGNATURES.items():
        if header.startswith(magic):
            return kind
    return "inconnu"

print(detect_type("invoice.pdf"))   # PDF
print(detect_type("photo.jpg"))     # PNG !
  • "rb" : lecture binaire, on obtient des bytes
  • Les premiers octets d'un fichier, les magic bytes, révèlent son vrai format
  • photo.jpg est en réalité un PNG
On reconnaît un fichier à son contenu, pas à son extension : un réflexe de base du forensic.
Un malware déguisé en invoice.pdf.exe ou une image qui cache une archive : l'extension ne prouve rien. La commande file sous Linux et macOS fait exactement ce travail.

Empreinte SHA-256


import hashlib

print(hashlib.sha256(b"Fondation").hexdigest())
# 9dff5c74a4ea8611…eef425fd
print(hashlib.sha256(b"fondation").hexdigest())
# 7e1f6f4f4672b3fa…3a988cbc

def file_sha256(path):
    digest = hashlib.sha256()
    with open(path, "rb") as f:
        while True:
            chunk = f.read(65536)   # blocs de 64 Ko
            if not chunk:
                break
            digest.update(chunk)
    return digest.hexdigest()
  • Une empreinte (hash) résume n'importe quelles données en 64 caractères hexadécimaux
  • Une seule lettre change : l'empreinte change entièrement
  • Comparer deux empreintes permet de vérifier l'intégrité d'un fichier
SHA-256 seul ne suffit pas pour stocker des mots de passe : il est trop rapide. On utilise des fonctions lentes comme bcrypt ou argon2.
Empreintes complètes : Fondation → 9dff5c74a4ea8611996f5472159e01872bdfe3fb49a766405014d90eeef425fd ; fondation → 7e1f6f4f4672b3fa6652f219759357ab44a21cec7e32e0f36573b3c73a988cbc. Vérification croisée possible : shasum -a 256 fichier (macOS, Linux) ou Get-FileHash fichier (PowerShell). Pourquoi SHA-256 ne suffit pas pour les mots de passe : il est trop rapide, un attaquant en teste des milliards par seconde. D'où bcrypt ou Argon2.

word = "café"

Écrire et lire du JSON


import json

config = {"server": "srv-web", "ports": [22, 443],
          "mfa": True, "owner": "Équipe SOC"}

with open("config.json", "w", encoding="utf-8") as f:
    json.dump(config, f, indent=2, ensure_ascii=False)

with open("config.json", encoding="utf-8") as f:
    loaded = json.load(f)
print(loaded["ports"])            # [22, 443]

text = json.dumps(config)         # dict → str
print(json.loads(text)["mfa"])    # True
  • dump / load : vers ou depuis un fichier
  • dumps / loads : vers ou depuis une chaîne (le « s » de string)
  • indent=2 : un fichier lisible
  • ensure_ascii=False : les accents restent lisibles

    def to_dict(self):

Charger sans planter


def load_users(path):
    try:
        with open(path, encoding="utf-8") as f:
            data = json.load(f)
    except FileNotFoundError:
        return []                # premier lancement
    except json.JSONDecodeError:
        print("Sauvegarde corrompue")
        return []
    users = []
    for item in data:
        users.append(user_from_dict(item))
    return users

print(len(load_users("absent.json")))   # 0
print(len(load_users("users.json")))    # 2
  • Au premier lancement, la sauvegarde n'existe pas encore : ce n'est pas une erreur
  • Un fichier tronqué ou modifié à la main lève json.JSONDecodeError
  • Dans les deux cas, le programme démarre avec des données vides

🛡️ Côté sécurité


ROLES = ["analyste", "auditeur", "admin"]

def user_from_dict(data):
    if data.get("role") not in ROLES:
        raise ValueError(f"rôle inconnu : {data.get('role')}")
    return User(data["username"], data["role"])

user_from_dict({"username": "eve", "role": "root"})
# ValueError: rôle inconnu : root
  • Jamais de pickle ni d'eval() sur des données non fiables : ils peuvent exécuter du code caché dans le fichier
  • json ne fait que lire des données : il est sûr
  • Mais un fichier JSON se modifie à la main : les données chargées se valident, par liste blanche comme au TP1
Une empreinte SHA-256 de la sauvegarde permet de détecter toute modification du fichier.
pickle.load() sur un fichier piégé exécute du code arbitraire : c'est une vraie classe de vulnérabilités (désérialisation non sûre, catégorie de l'OWASP Top 10).
