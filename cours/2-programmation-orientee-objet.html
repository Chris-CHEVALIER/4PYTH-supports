#1

Pourquoi des objets ?

Programmation orientée objet

Les limites des dictionnaires

Au TP1, un membre d'équipage était un dictionnaire. Rien ne protège ses données :


user = {"username": "alice", "role": "analyste",
        "failed_attempts": 0}

user["role"] = "n'importe quoi"   # aucun contrôle
user["failed_attemps"] = 5        # faute de frappe :
                                  # une nouvelle clé !
  • Les données ne sont pas contrôlées
  • Les fonctions qui les manipulent sont ailleurs, dans un autre fichier
  • Rien ne dit quelles clés un compte doit avoir
La programmation orientée objet réunit les données et les comportements dans un même modèle, qui décide de ce qui est permis.
Partir du vécu du TP1 : les étudiants ont tous écrit des dictionnaires et des fonctions séparées. La faute de frappe « failed_attemps » ne provoque aucune erreur : elle crée silencieusement une nouvelle clé.

Le vocabulaire de l'objet

TermeDéfinitionExemple
ClasseLe modèle : il décrit les données et les actions communesUser
Objet (instance)Un exemplaire concret, créé à partir de la classealice
AttributUne donnée propre à l'objet : son étatalice.role
MéthodeUne action que l'objet sait faire : une fonction de la classealice.record_failure()
InstancierCréer un objet à partir de sa classeUser("alice", "analyste")
La classe est le formulaire vierge de création de compte ; chaque compte créé à partir de ce formulaire est un objet.
#2

Classes et objets

Programmation orientée objet

Définir une classe


class User:
    """Un compte utilisateur."""

    def __init__(self, username, role):
        self.username = username
        self.role = role
        self.failed_attempts = 0
        self.is_locked = False
  • class User: définit la classe, nommée en PascalCase
  • __init__ est le constructeur : il est appelé automatiquement à la création de chaque objet
  • self désigne l'objet en cours de création : self.role = role range la valeur dans cet objet
  • Un attribut peut avoir une valeur de départ fixe : failed_attempts = 0
Insister sur self : c'est le premier paramètre de toute méthode, Python le remplit tout seul. Les attributs n'existent qu'une fois assignés à self.

Créer des objets


alice = User("alice", "analyste")
bob = User("bob", "auditeur")

print(alice.username)        # alice
print(bob.role)              # auditeur
print(type(alice))           # <class '__main__.User'>

alice.failed_attempts = 2
print(bob.failed_attempts)   # 0
  • On appelle la classe comme une fonction : Python crée l'objet puis exécute __init__
  • On accède aux attributs avec le point : alice.username
  • Chaque objet a ses propres attributs : modifier alice ne touche pas bob
  • Le type de l'objet est sa classe

Les méthodes


class User:
    def __init__(self, username, role):
        ...  # comme sur la diapo précédente

    def record_failure(self):
        """Enregistre un échec et verrouille au 3e."""
        self.failed_attempts += 1
        if self.failed_attempts >= 3:
            self.is_locked = True

alice = User("alice", "analyste")
for _ in range(3):
    alice.record_failure()
print(alice.is_locked)       # True
  • Une méthode est une fonction définie dans la classe
  • Son premier paramètre est toujours self : elle agit sur l'objet qui l'appelle
  • alice.record_failure() revient à écrire User.record_failure(alice)
  • La règle de verrouillage est écrite une seule fois, au plus près des données
Les points de suspension (...) sont un vrai mot-clé Python : ici, ils signifient « le code déjà vu ».

Attributs de classe ou d'instance


class User:
    MAX_ATTEMPTS = 3      # attribut de classe

    def __init__(self, username, role):
        self.username = username   # d'instance
        ...

    def record_failure(self):
        self.failed_attempts += 1
        if self.failed_attempts >= User.MAX_ATTEMPTS:
            self.is_locked = True

print(User.MAX_ATTEMPTS)     # 3
print(alice.MAX_ATTEMPTS)    # 3 : lu depuis la classe
  • Attribut d'instance (self.x) : une valeur par objet
  • Attribut de classe : une seule valeur, partagée par tous les objets
  • Idéal pour une constante de la classe : on ne répète plus le nombre 3 dans le code
Au TP2, la capacité maximale d'un vaisseau (10 membres) sera un attribut de classe.

Afficher un objet : __str__

Sans __str__


>>> print(alice)
<__main__.User object at 0x10291aa50>

Avec __str__


class User:
    ...
    def __str__(self):
        state = "actif"
        if self.is_locked:
            state = "verrouillé"
        return f"{self.username} ({self.role}, {state})"

print(alice)    # alice (analyste, verrouillé)
  • __str__ est une méthode spéciale : print() et str() l'appellent automatiquement
  • Elle renvoie une chaîne, elle ne l'affiche pas
  • Les méthodes entourées de __ (dunder) sont réservées à Python : __init__, __str__…

Qu'affiche ce programme ?


class Probe:
    total = 0
    def __init__(self, name):
        self.name = name
        self.hits = 0
        Probe.total += 1
    def hit(self):
        self.hits += 1
        return self.hits

ssh = Probe("ssh")
web = Probe("web")
ssh.hit()
ssh.hit()
web.hit()
print(ssh.hits, web.hits)
print(Probe.total)
print(ssh.hit())
2 1 : chaque sonde compte ses propres passages
2 : total est un attribut de classe, incrémenté à chaque création
3 : hit() incrémente puis renvoie la nouvelle valeur
Laisser 30 secondes, faire répondre à l'oral, puis révéler ligne par ligne. Réponses : 2 1 · 2 · 3. Le piège : total est partagé, hits est propre à chaque objet.

Encapsulation

Programmation orientée objet

Le principe et les conventions

L'encapsulation consiste à garder la maîtrise des données d'un objet : on les modifie par ses méthodes plutôt que directement.


class User:
    def __init__(self, username, password):
        self.username = username      # public
        self._sessions = []           # usage interne
        self.__password = password    # nom modifié
NomSignification
usernamepublic
_sessions« ne pas toucher » : simple convention
__passwordrenommé en _User__password
En Python, rien n'est vraiment privé. Le _ n'est pas « réservé aux classes filles » : c'est un signal adressé aux autres développeurs, que Python ne vérifie pas.
Correction par rapport à l'ancienne version du cours : le simple underscore n'impose aucune restriction d'accès.

🛡️ Côté sécurité


>>> alice = User("alice", "S3cr3t!")
>>> alice.__password
AttributeError: 'User' object has no attribute
'__password'
>>> alice._User__password
'S3cr3t!'
>>> vars(alice)
{'username': 'alice', '_sessions': [],
 '_User__password': 'S3cr3t!'}
  • Le double underscore ne fait que renommer l'attribut
  • vars() affiche tous les attributs d'un objet, « privés » compris
L'encapsulation n'est pas un mécanisme de sécurité. Elle protège contre les erreurs, pas contre un attaquant. Un secret ne se stocke jamais en clair : il se hache avec une fonction dédiée comme bcrypt ou argon2.
Point clé pour un public cyber. Faire le parallèle avec un mot de passe « caché » dans le code source d'une application : quiconque a accès au code ou à la mémoire du processus le récupère.

@property : un attribut en lecture seule


class User:
    def __init__(self, username):
        self.username = username
        self._failed_attempts = 0

    @property
    def failed_attempts(self):   # lecture seule
        return self._failed_attempts

alice = User("alice")
print(alice.failed_attempts)     # 0
alice.failed_attempts = 5
# AttributeError: property 'failed_attempts'
#   of 'User' object has no setter
  • @property transforme une méthode en attribut calculé : on l'utilise sans parenthèses
  • Sans setter, l'attribut est en lecture seule
  • Seules les méthodes de la classe, comme record_failure(), modifient _failed_attempts
C'est la façon pythonique de remplacer les get_…() et set_…() d'autres langages.

@property : valider une écriture


ROLES = ["analyste", "auditeur", "admin"]

class User:
    def __init__(self, username, role):
        self.username = username
        self.role = role          # passe par le setter

    @property
    def role(self):
        return self._role

    @role.setter
    def role(self, value):
        if value not in ROLES:
            raise ValueError(f"rôle inconnu : {value}")
        self._role = value
        

alice = User("alice", "analyste")
alice.role = "auditeur"   # accepté
alice.role = "hacker"
# ValueError: rôle inconnu : hacker
  • Le setter s'exécute à chaque affectation, y compris dans __init__
  • Le rôle est validé par liste blanche, comme au TP1
Faire remarquer que self.role = role dans __init__ passe déjà par le setter : un objet ne peut pas naître dans un état invalide.

Héritage et polymorphisme

Programmation orientée objet

Hériter d'une classe


class Admin(User):
    def __init__(self, username, scope):
        super().__init__(username, "admin")
        self.scope = scope     # attribut en plus

root = Admin("root", "serveurs Linux")
print(root.username, root.role)   # root admin
root.record_failure()             # méthode héritée
print(root.failed_attempts)       # 1
print(isinstance(root, User))     # True
  • class Admin(User): : la classe fille Admin hérite de la classe mère User
  • Elle récupère tous ses attributs et toutes ses méthodes
  • super().__init__(…) appelle le constructeur de la classe mère : sans lui, username n'existerait pas
  • Un Admin est un User
Oublier super().__init__ est l'erreur la plus fréquente au TP2 (Operator et Mentalist héritent de Person).

Redéfinir une méthode


class User:
    ...
    def describe(self):
        return f"Compte {self.username} ({self.role})"

class Admin(User):
    ...
    def describe(self):          # redéfinition
        return f"Administrateur {self.username}"

print(User("alice", "analyste").describe())
# Compte alice (analyste)
print(Admin("root", "serveurs Linux").describe())
# Administrateur root
  • La classe fille peut remplacer une méthode héritée en la redéfinissant avec le même nom
  • Python utilise toujours la version la plus proche de la classe de l'objet
On parle de redéfinition (override), pas de surcharge. La surcharge (plusieurs méthodes de même nom avec des paramètres différents) n'existe pas en Python.
Correction par rapport à l'ancienne version du cours, qui parlait de « surcharge ».

Étendre une méthode avec super()


class Admin(User):
    ...
    def describe(self):
        base = super().describe()    # version de User
        return f"{base} – périmètre : {self.scope}"

root = Admin("root", "serveurs Linux")
print(root.describe())
# Compte root (admin) – périmètre : serveurs Linux
  • super() donne accès à la version de la classe mère
  • On réutilise son résultat au lieu de le réécrire : moins de code dupliqué
  • Si le format de User.describe() change, Admin suit automatiquement

Le polymorphisme


accounts = [
    User("alice", "analyste"),
    Admin("root", "serveurs Linux"),
    User("bob", "auditeur"),
]
for account in accounts:
    print(account.describe())
          

Compte alice (analyste)
Compte root (admin) – périmètre : serveurs Linux
Compte bob (auditeur)
  • Un même appel produit un comportement adapté au type de chaque objet
  • La boucle n'a pas besoin de savoir qui est administrateur
Au TP2, act() fera agir un opérateur et un mentaliste chacun à sa manière.

Tester le type : isinstance()


admins = 0
for account in accounts:
    if isinstance(account, Admin):
        admins += 1
print(admins)                           # 1

print(isinstance(accounts[1], User))    # True
print(type(accounts[1]) == User)        # False
  • isinstance(objet, Classe) est vrai si l'objet est de cette classe ou d'une classe fille
  • type(…) == … ignore l'héritage : préférez isinstance()
  • Pratique pour compter par type : administrateurs, mentalistes…
Au TP2, statistics() de la flotte comptera les membres par type et par rôle.

Qu'affiche ce programme ?


class Alert:
    def __init__(self, source):
        self.source = source
    def level(self):
        return "info"
    def report(self):
        return f"[{self.level()}] {self.source}"

class CriticalAlert(Alert):
    def level(self):
        return "CRITIQUE"

alerts = [Alert("ssh"), CriticalAlert("firewall")]
for alert in alerts:
    print(alert.report())
print(isinstance(alerts[1], Alert))
[info] ssh : méthodes de Alert
[CRITIQUE] firewall : report() est héritée, mais self.level() appelle la version redéfinie
True : une CriticalAlert est une Alert
Réponses : [info] ssh · [CRITIQUE] firewall · True. Le piège est la 2e ligne : même dans une méthode héritée, self.level() choisit la version de la classe de l'objet.

Composition

Programmation orientée objet

« Est un » ou « a un » ?

RelationExempleEn Python
Est un → héritageUn administrateur est un utilisateurclass Admin(User):
A un → compositionUn réseau a des serveursself.servers = []

class Server:
    def __init__(self, hostname, ip, services):
        self.hostname = hostname
        self.ip = ip
        self.services = services   # liste de chaînes
La composition consiste à ranger des objets dans les attributs d'un autre objet. En cas de doute, préférez-la à l'héritage.

Des objets dans des objets


class Network:
    MAX_SERVERS = 3

    def __init__(self, name):
        self.name = name
        self.servers = []          # objets Server

    def add_server(self, server):
        if len(self.servers) >= Network.MAX_SERVERS:
            raise ValueError("capacité maximale atteinte")
        self.servers.append(server)

    def find_by_ip(self, ip):
        for server in self.servers:
            if server.ip == ip:
                return server
        return None
        

dmz = Network("DMZ")
dmz.add_server(Server("web01",
    "10.0.1.10", ["http", "https"]))
dmz.add_server(Server("mail01",
    "10.0.1.20", ["smtp"]))
dmz.find_by_ip("10.0.1.20").hostname
# 'mail01'
  • Le réseau contrôle ce qu'on lui ajoute : capacité maximale
  • Au TP2 : Spaceship a un équipage, Fleet a des vaisseaux
Au 4e serveur, add_server lève ValueError: capacité maximale atteinte (testé). find_by_ip renvoie None si l'adresse est inconnue : même logique que find_member au TP1.
